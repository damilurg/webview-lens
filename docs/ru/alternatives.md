# Альтернативы: chrome://inspect, Safari Web Inspector, Eruda, HTTP-прокси

Чем webview-lens отличается от инструментов, которыми уже отлаживают веб-страницу внутри мобильного
приложения, и когда лучше выбрать один из них.

| Задача                                      | `chrome://inspect` | Safari Web Inspector | `ios_webkit_debug_proxy`  | Eruda / vConsole        | HTTP-прокси (Charles, Proxyman) | webview-lens |
| ------------------------------------------- | ------------------ | -------------------- | ------------------------- | ----------------------- | ------------------------------- | ------------ |
| Android WebView                             | ✓                  | —                    | —                         | ✓ (встраиваемый скрипт) | только сеть                     | ✓            |
| iOS WKWebView                               | —                  | ✓                    | ✓                         | ✓ (встраиваемый скрипт) | только сеть                     | ✓            |
| Отладка iOS на Windows                      | —                  | —                    | ✓ (без своего интерфейса) | ✓                       | только сеть                     | ✓            |
| Полные Chrome DevTools на постоянном адресе | —                  | —                    | —                         | —                       | —                               | ✓            |
| Локальный dev-сервер под HTTPS приложения   | —                  | —                    | —                         | —                       | ✓ (Map Remote)                  | ✓ (с HMR)    |
| Логи WebView в терминале                    | —                  | —                    | —                         | —                       | —                               | ✓            |

## `chrome://inspect`

Встроен в Chrome, ничего ставить не нужно, для быстрого взгляда на Android WebView его хватает.
Вкладка DevTools умирает при перезапуске приложения, для iOS ничего нет, а страница по-прежнему
работает с выложенным сайтом, а не с вашим dev-сервером. webview-lens использует тот же сокет
DevTools на Android и добавляет постоянный адрес, переподключение, `--logs`, `dev` и `vitals`.

## Safari Web Inspector

Родной инструмент для WKWebView и лучший выбор, если вы работаете на Mac: в нём собственные панели
WebKit. Ему нужен Mac, у него нет командной строки, и его нельзя направить на ваш dev-сервер. На
Windows, или чтобы пользоваться Chrome DevTools, терминалом и теми же командами, что на Android,
берите webview-lens.

## `ios_webkit_debug_proxy`

Прокси от инспектора iPhone к WebSocket; webview-lens запускает его на iOS сама. Сам по себе он не
даёт интерфейса DevTools и говорит на протоколе WebKit, который Chrome DevTools не понимают;
webview-lens переводит его.

## Eruda и vConsole

Консоль, нарисованная прямо на странице. Работает на любом телефоне без кабеля, что удобно для
устройства тестировщика или отчёта об ошибке из продакшена. Это скрипт, который вы поставляете (или
внедряете); он видит только то, что видит JavaScript, и у него нет отладчика, профайлера и
настоящей панели сети.

## HTTP-прокси (Charles, Proxyman, mitmproxy)

Правильный инструмент, чтобы смотреть и подменять трафик, включая запросы самого нативного
приложения. Map Remote умеет отдавать локальные файлы, но без WebSocket для HMR, и страницы прокси
не видит: ни консоли, ни DOM, ни производительности. Режим `dev` на iOS в webview-lens — прокси
такого же рода, который перехватывает только ваш домен и пробрасывает сокет HMR.

## Нативные профайлеры

Android Studio и Xcode профилируют процесс приложения. Для веб-страницы внутри него больше дают
DevTools самого браузерного движка: к ним webview-lens и подключается.
