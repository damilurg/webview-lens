# Настройка iOS WKWebView (macOS и Windows)

`webview-lens` поддерживает инспекцию, локальную подмену кода и замеры для iOS `WKWebView` с **macOS** и **Windows** без runtime-зависимостей.

## 1. Предварительные требования

| Требование                                         | macOS                                                    | Windows                                                                            |
| -------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **USB-транспорт (`usbmuxd`)**                      | Встроен в macOS (`/var/run/usbmuxd`)                     | Установить **Apple Devices** или **iTunes** из Microsoft Store (`127.0.0.1:27015`) |
| **WebInspector-прокси (`ios_webkit_debug_proxy`)** | `brew install ios-webkit-debug-proxy`                    | `scoop install ios-webkit-debug-proxy` (или распаковать в `~/Downloads`)           |
| **Флаг в тестовой сборке**                         | `webView.isInspectable = true` (iOS 16.4+)               | `webView.isInspectable = true` (iOS 16.4+)                                         |
| **Настройка на iPhone**                            | _Настройки → Safari → Дополнительно → Веб-инспектор_ ВКЛ | _Настройки → Safari → Дополнительно → Веб-инспектор_ ВКЛ                           |

Проверить готовность:

```bash
npx webview-lens doctor --platform ios
```

## 2. Инспекция в Chrome DevTools и live-логи (macOS и Windows)

```bash
npx webview-lens devtools --platform ios --logs
```

- Автоматически запускает `ios_webkit_debug_proxy`, если он установлен, но ещё не запущен.
- Открывает Chrome DevTools на `http://localhost:3300` через встроенный **WIP ↔ CDP мост**.
- С флагом `--logs` выводит `console.*` и ошибки сетевых запросов прямо в терминал.

## 3. Локальный dev-сервер внутри тестовой сборки iOS (`webview-lens dev`)

Поскольку в WebKit Inspector Protocol нет аналога CDP `Fetch.fulfillRequest`, `webview-lens` использует **selective HTTPS MITM-прокси**: он расшифровывает и перенаправляет на `localhost` **только** домен `--remote` (HTTP + нативный WebSocket HMR), а весь остальной трафик пропускает без вмешательства через raw TCP `CONNECT`.

### Одноразовая установка Root CA на тестовый iPhone

```bash
npx webview-lens cert
```

1. Наведите камеру iPhone на QR-код в терминале (или откройте `http://<ваш-lan-ip>:8888/` в Safari).
2. Нажмите **Download iOS Profile (.mobileconfig)** и разрешите загрузку.
3. Откройте **Настройки → Основные → VPN и управление устройством** и установите профиль _webview-lens Local CA_.
4. Откройте **Настройки → Основные → Об этом устройстве → Доверие сертификатам** и включите полное доверие для _webview-lens Local CA_.
5. Убедитесь, что в тестовой/debug iOS-сборке **отключён SSL Pinning**.

### Запуск локальной подмены

```bash
npx webview-lens dev http://localhost:5173 --platform ios --remote https://stand.example.com --cmd "npm run dev" --logs
```

На iPhone откройте **Настройки → Wi-Fi → (i) → Настройка прокси → Вручную** и укажите IP и порт из вывода терминала (по умолчанию `8888`). Откройте WebView-экран в приложении — страница и HMR начнут загружаться с вашего локального dev-сервера.

Прокси слушает все интерфейсы, но обслуживает только клиентов с loopback, частных (`10/8`, `172.16/12`, `192.168/16`, `fc00::/7`), link-local и CGNAT (`100.64/10`) адресов, поэтому на публичном интерфейсе он не становится открытым прокси. Правило меняется опцией `allowClient` в `startIosMitmProxy`. Локальный dev-сервер по `https://` (Vite/Angular `--https`) тоже работает для WebSocket HMR; его самоподписанный сертификат принимается только для `localhost`.

### Как работает прокси, по шагам

`webview-lens dev --platform ios` запускает на маке один HTTP-прокси (порт `8888`). iPhone отправляет
туда **весь** трафик Wi-Fi; прокси расшифровывает только хост из `--remote` своим CA и отдаёт его с
вашего локального dev-сервера, а остальные хосты пропускает как есть.

| Шаг | На iPhone                                                                                  | Что должно получиться                                            |
| --- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 1   | Safari: **`http://<ip-мака>:8888/`** (http, не https)                                      | страница «webview-lens iOS setup» с кнопкой профиля              |
| 2   | Скачать профиль, затем Настройки → Основные → VPN и управление устройством → установить    | профиль «webview-lens Local CA» установлен                       |
| 3   | Настройки → Основные → Об этом устройстве → Доверие сертификатам → включить полное доверие | переключатель «webview-lens Local CA» включён                    |
| 4   | Настройки → Wi-Fi → (i) → Настроить прокси → **Вручную**: сервер `<ip-мака>`, порт `8888`  | —                                                                |
| 5   | Safari: **`http://webview-lens.check/`**                                                   | **Proxy: OK** (и `proxy check OK` в терминале)                   |
| 6   | Safari: **`https://<хост-стенда>/__webview-lens/ok`**                                      | **Interception: OK** (и `interception check OK` в терминале)     |
| 7   | Открыть приложение (или стенд в Safari)                                                    | ваша локальная сборка, в терминале строки запросов (`200 GET /`) |
| 8   | После работы: Настроить прокси → **Выкл.**                                                 | обычный интернет без мака                                        |

### Если не работает

| Симптом                                                                       | Причина                                                    | Что сделать                                                                                                            |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Safari не открывает `https://<ip-мака>:8888/` (ошибка TLS)                    | порт прокси работает по обычному HTTP                      | открыть `http://<ip-мака>:8888/`                                                                                       |
| `http://webview-lens.check/` не открывается                                   | iPhone не ходит через прокси                               | Настроить прокси → Вручную в той Wi-Fi-сети, где вы сейчас; сервер — IP из терминала (проверьте опечатки), порт `8888` |
| Проверка открывается, а `…/__webview-lens/ok` пишет «Подключение не защищено» | CA установлен, но доверие не включено                      | шаг 3: Доверие сертификатам → включить полное доверие                                                                  |
| Обе проверки проходят, а приложение показывает стенд                          | приложение пинит сертификаты, или страница из кеша         | тестовая сборка без SSL pinning; перезагрузить экран (или Enter в терминале)                                           |
| В терминале нет строк `200 GET …`, только `[console…]`                        | `--logs` идёт по USB, а сама страница не идёт через прокси | сначала шаг 5                                                                                                          |
| `MITM FAIL … (UNABLE_TO_VERIFY_LEAF_SIGNATURE)` для путей из `--bypass`       | у стенда частный CA, которому Node не доверяет             | запускать с `NODE_EXTRA_CA_CERTS=/путь/к/stand-ca.pem`                                                                 |
| `Proxy refused client … (not a private network)`                              | клиент не из частной сети                                  | использовать LAN-IP мака в той же Wi-Fi-сети                                                                           |
| После остановки `dev` на iPhone пропал интернет                               | прокси Wi-Fi всё ещё указывает на мак                      | Настроить прокси → Выкл.                                                                                               |
