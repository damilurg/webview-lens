# How it was verified

What webview-lens claims, how each claim was checked on real phones, what was observed, and which
test keeps it from breaking. Tests use doubles that replay what the devices did (captured with
`--log-file` or `webview-lens keyboard`), so a regression fails CI without a phone.

## Test bed

| Part     | What                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Android  | Redmi Note 8 Pro, Android 11, Android System WebView 157, over USB (`adb`)                                                                                                 |
| iPhone   | iPhone 17 Pro, iOS 26.6.1, over USB (`usbmuxd`, `ios_webkit_debug_proxy`) and Wi-Fi to the Mac                                                                             |
| Apps     | A Kotlin app (Android) and a Flutter app (`webview_flutter`, Android and iOS), both signing in natively and opening the stand in a WebView with a JS bridge                |
| Stand    | An HTTPS origin with its own CA: sign-in API, session cookie, RUM collector with Prometheus `/metrics`; as a static host or a reverse proxy in front of a framework server |
| Web apps | Vite, Next.js 16 (SSR, SSG, Server Action, static export), Nuxt 4, SvelteKit 3, Angular 22                                                                                 |
| Date     | 2026-11-25 – 2026-11-26                                                                                                                                                    |

## Found on the phones and fixed

Each of these passed the tests that existed at the time, because their doubles followed our
assumptions. The tests now replay what the device did.

| Found                                                                                                                                                                    | Where            | Fix and test                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| The `angular` preset bridged `/ng-cli-ws` (webpack era); Angular 17+ HMR runs on Vite at the page origin                                                                 | Android, Angular | preset bridges `/`; `test/presets.test.ts`                                                                                   |
| `dev` kept serving a WebView the app had replaced (rotation)                                                                                                             | Android, Kotlin  | follows the one on screen (not re-run on the phone); `test/device.test.ts`                                                   |
| `--wl-keyboard-height` was 17 px too high after the WebView got shorter (a native status line appeared)                                                                  | iPhone, Flutter  | baseline resets while no field is focused; `test/web/viewport.test.ts`                                                       |
| iOS overscroll (`visualViewport.offsetTop` −3 px) added to the keyboard height                                                                                           | iPhone           | negative offsets ignored; `test/web/viewport.test.ts`                                                                        |
| A fixed bottom bar riding on the keyboard hid the field `keepFocusedInputVisible` had just made "visible"                                                                | iPhone, Flutter  | fixed and sticky bars counted (`unobstructedBottom`); `test/web/viewport.test.ts`                                            |
| `vitals https://…` (a URL instead of a path) failed on Android and printed dashes on iOS                                                                                 | both             | clear error; `test/bdd/cli.bdd.test.ts`                                                                                      |
| Prerendered HTML without `Cache-Control` stayed cached in both WebViews after a deploy                                                                                   | both, Nuxt       | documented with the fix ([SSR](ssr.md)); a stand behaviour, not a library one                                                |
| On iOS client coordinates follow the visual viewport: a field under the keyboard looked visible to `keepFocusedInputVisible`                                             | iPhone, Flutter  | `visibleBottomInClient` tells which from the root's rect; `test/web/viewport.test.ts`                                        |
| `scrollIntoView` centred the field in the layout viewport, part of which is under the keyboard                                                                           | iPhone           | scroll by a computed delta (`revealDelta`); `test/web/viewport.test.ts`                                                      |
| The page had no room to scroll its last fields above the keyboard (WKWebView in an app adds none)                                                                        | iPhone, Flutter  | `--wl-scroll-room`; `test/web/viewport.test.ts`                                                                              |
| `innerHeight` shrank 714 → 680 while a field in a fixed bar was focused, and the bar went 33 px under the keyboard                                                       | iPhone, Flutter  | layout height from the root `clientHeight`; Flutter: `contentInsetAdjustmentBehavior = .never`                               |
| `--wl-keyboard-height` dropped to 195 px while the visual viewport panned                                                                                                | iPhone           | the pan no longer counts; `test/web/viewport.test.ts`                                                                        |
| Flutter resizing the WKWebView made WebKit scroll a newly focused field by the old geometry                                                                              | iPhone, Flutter  | Flutter recipe: `resizeToAvoidBottomInset: !Platform.isIOS`                                                                  |
| `attachTelemetry()` without options printed nothing: the page console went to the library's silent logger                                                                | iPhone, Flutter  | prints to stdout / stderr by default; `test/telemetry.test.ts`                                                               |
| Each new attach showed the page's console history as new lines (2, 3, 4 copies on successive runs)                                                                       | iPhone, Flutter  | history marked `(earlier)` or skipped; `test/telemetry.test.ts`                                                              |
| `evaluate('fetch(…)')` gave `{}`                                                                                                                                         | iPhone           | `awaitPromise`; `test/base-session.test.ts`                                                                                  |
| The computer's address changed (192.168.94.216 → 192.168.86.130): the WebView hung on "loading", sign-in failed with `SocketException`, nothing in webview-lens said why | iPhone, Flutter  | `dev` reports the change and a phone that never connects; `doctor` flags pages on an old address; `test/ios-network.test.ts` |
| `devtools` on iOS attached to a WebView behind another screen: Elements worked, the Console ran nothing                                                                  | iPhone, Flutter  | the page on screen is picked (`findVisibleTarget`); `test/visible-target.test.ts`                                            |
| A page that never answers kept its socket open forever; enough of them jammed `ios_webkit_debug_proxy`                                                                   | iPhone           | `connectInspector` gives up after 5 s and closes the socket; `test/bdd/ios-inspector.bdd.test.ts`                            |
| The Console had no execution context: WebKit's `executionContextCreated` was passed in WebKit's shape                                                                    | iPhone, Chrome   | translated to CDP (`uniqueId`, `auxData.isDefault`); `test/ios-wip-bridge.test.ts`                                           |
| Top-level `await` in the Console was a SyntaxError (WebKit has no `replMode`); errors printed twice; objects without preview                                             | iPhone, Chrome   | wrapped and awaited by the bridge; `text: 'Uncaught'`; `generatePreview` passed; `test/ios-wip-bridge.test.ts`               |

## Not verified, or known not to work

- **Swift (UIKit/SwiftUI) apps** and **React Native:** the recipes follow Apple's documentation; no test app.
- **Android 15+ edge-to-edge** (`adjustResize` no longer resizes): recipe from the platform docs; the test phone runs Android 11.
